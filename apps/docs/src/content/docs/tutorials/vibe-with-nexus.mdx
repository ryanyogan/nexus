## Introduction

"Vibe coding" with Nexus means letting your AI assistant naturally use documentation and memory to help you code. This tutorial shows how to get the most out of Nexus in your daily workflow.

## The Vibe Workflow

### 1. Start with Context

When starting a new session, let your AI know about your project:

> **You:** I'm working on my Next.js e-commerce app. We use TanStack Query for data fetching and Stripe for payments.

The AI will save this context (if it hasn't already) and use it throughout your session.

### 2. Ask Natural Questions

Don't worry about specific tool syntax - just ask naturally:

> **You:** How do I handle Stripe webhooks in Next.js API routes?

The AI will automatically:
1. Resolve the relevant libraries (Next.js, Stripe)
2. Query their documentation
3. Provide an answer with code examples

### 3. Let It Remember

When you make decisions or learn something important:

> **You:** Save this: We're using Stripe webhooks with signature verification. The endpoint is /api/webhooks/stripe.

Later, when you (or someone else) ask about webhooks, the AI will recall this.

### 4. Keep the Flow

Don't break your flow to manually search docs. Just ask:

> **You:** What's the TypeScript type for a Stripe checkout session?

The AI fetches the exact type definition from Stripe's docs.

## Example Session

Here's a realistic vibe coding session:

---

> **You:** I need to add product search to my app. We're using Algolia.

> **AI:** I'll help you add Algolia search. Let me check the latest Algolia docs...
>
> *(Uses resolve-library and query-docs)*
>
> Here's how to set up Algolia InstantSearch in Next.js:
>
> ```tsx
> import { InstantSearch, SearchBox, Hits } from 'react-instantsearch';
> import algoliasearch from 'algoliasearch/lite';
> 
> const searchClient = algoliasearch('APP_ID', 'SEARCH_KEY');
> 
> export function ProductSearch() {
>   return (
>     <InstantSearch searchClient={searchClient} indexName="products">
>       <SearchBox />
>       <Hits hitComponent={Hit} />
>     </InstantSearch>
>   );
> }
> ```

---

> **You:** What about the environment variables for the API keys?

> **AI:** For Next.js, you'll want:
>
> ```env
> NEXT_PUBLIC_ALGOLIA_APP_ID=your_app_id
> NEXT_PUBLIC_ALGOLIA_SEARCH_KEY=your_search_key
> ALGOLIA_ADMIN_KEY=your_admin_key  # Server-only
> ```
>
> Note: The search key can be public (prefixed with `NEXT_PUBLIC_`), but keep the admin key server-side only.

## Tips for Better Vibes

### Be Conversational

Don't format your questions like search queries. Talk naturally:

- Instead of: "react usestate array update"
- Try: "How do I add an item to a state array in React without mutating it?"

### Build on Context

Reference previous discussions:

- "Going back to that Stripe webhook - how do I test it locally?"
- "For the search we just added, how do I add filters?"

### Save Decisions

When you decide something, save it:

- "Save this decision: We're using Algolia for search instead of building our own because..."

### Start Sessions with Recall

Begin sessions by mentioning your project:

- "Let's continue working on the e-commerce app"

The AI will automatically recall relevant context.

## Common Patterns

### Learning a New Library

> "I'm trying to learn Drizzle ORM. What are the basics?"

The AI will pull introductory content and guide you.

### Debugging

> "I'm getting a hydration error in React. What causes these and how do I fix them?"

Documentation search finds common causes and solutions.

### Best Practices

> "What's the recommended way to structure a monorepo with Turborepo?"

Get up-to-date recommendations from official docs.
