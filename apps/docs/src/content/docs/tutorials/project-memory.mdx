## Introduction

Nexus memory is what makes AI coding assistants truly useful across sessions. Instead of re-explaining your project every time, the AI remembers your architecture, decisions, and lessons learned.

## Memory Types

### project_context

**What:** Core information about your project that rarely changes.

**When to save:**
- Project setup (tech stack, architecture)
- Team conventions (naming, file structure)
- Integration details (APIs, databases)

**Example:**

> "Save this project context: This is a pnpm monorepo with three apps: web (Next.js), api (Hono), and admin (React). We use Cloudflare Workers for deployment, D1 for the database, and R2 for file storage."

### decision

**What:** Architectural or technical decisions with their rationale.

**When to save:**
- After making important technical choices
- When choosing between options
- After team discussions

**Example:**

> "Save this decision: Chose Drizzle ORM over Prisma because Drizzle has better Cloudflare D1 support and smaller bundle size. Trade-off is less mature ecosystem."

### correction

**What:** Lessons learned, mistakes to avoid.

**When to save:**
- After debugging a tricky issue
- When you discover a gotcha
- After wasting time on something

**Example:**

> "Save this correction: Don't use fetch() in Next.js server components for internal API calls - it causes extra network hops. Use direct database/function calls instead."

### session_summary

**What:** What was accomplished in a coding session.

**When to save:**
- End of each significant session
- Before context window limits
- When switching tasks

**Example:**

> "Save session summary: Implemented user profile page with avatar upload. Used R2 for storage with presigned URLs. Added image resize with Sharp. TODO: Add crop functionality."

## Memory Strategies

### 1. Start-of-Project Setup

When starting a new project, save foundational context:

```
Save project context for "myapp":
- Monorepo structure: pnpm workspaces
- Frontend: Next.js 14 with App Router
- Backend: Hono on Cloudflare Workers  
- Database: D1 with Drizzle ORM
- Auth: Better Auth with Google OAuth
- Styling: Tailwind CSS + shadcn/ui
```

### 2. Decision Documentation

When you make a choice:

```
Save decision for "myapp":
Title: State Management Approach
Decision: Using TanStack Query for server state, Zustand for client state
Rationale: TanStack Query handles caching/sync well, Zustand is minimal for UI state
Alternatives considered: Redux, Jotai, React Context
```

### 3. Learning Capture

When you learn something:

```
Save correction for "myapp":
Issue: Hydration mismatch errors
Cause: Using Date.now() in component render
Solution: Use useEffect for client-only values or suppressHydrationWarning
```

### 4. Session Continuity

End sessions with summaries:

```
Save session summary for "myapp":
Completed:
- User authentication flow
- Profile settings page
- Avatar upload with R2

In progress:
- Email notification system

Blockers:
- Need to set up Resend account for emails
```

## Recall Strategies

### Start of Session

> "Get context for myapp"

The AI retrieves your project context, recent decisions, and last session summary.

### Specific Topics

> "What did we decide about authentication?"

Semantic search finds relevant decisions.

### Debugging Help

> "Are there any known issues with date handling?"

Finds corrections related to your query.

### Team Onboarding

> "Summarize the architecture of myapp"

New team members can get up to speed from stored context.

## Best Practices

### Do's

- **Use consistent project names** - "myapp" not "my-app" or "MyApp"
- **Be specific in titles** - "Auth Flow Decision" not "Decision 1"
- **Include rationale** - Future you will thank present you
- **Save regularly** - Don't wait until the end
- **Update outdated context** - Architectures evolve

### Don'ts

- **Don't save sensitive data** - No API keys, passwords, or secrets
- **Don't duplicate** - Check if context exists before saving
- **Don't be too verbose** - Memory is for recall, not documentation
- **Don't forget to use it** - Start sessions with recall

## Organizing Large Projects

For large projects, use tags:

```
Save project context for "myapp":
Tags: ["frontend", "architecture"]
Content: Next.js App Router with file-based routing...

Save project context for "myapp":
Tags: ["backend", "architecture"]  
Content: Hono API with middleware chain...
```

Then recall by tag:

> "Get all frontend context for myapp"

## Team Usage

For teams, establish conventions:

1. **Shared project name** - Everyone uses the same name
2. **Decision template** - Standard format for decisions
3. **Summary schedule** - Daily or per-PR summaries
4. **Review corrections** - Team learns from each other's mistakes
