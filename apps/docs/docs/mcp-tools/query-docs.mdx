# query-docs

Search documentation for a specific library using semantic search. Returns relevant code examples, API references, and explanations.

<ApiEndpoint method="POST" path="/mcp/tools/query-docs" />

## Overview

The `query-docs` tool performs vector-based semantic search across indexed library documentation. It understands the meaning of your query, not just keywords, so it can find relevant results even when exact terms don't match.

:::note Two-step pattern
You must call `resolve-library` first to get the library ID, unless you already know it.
:::

---

## Parameters

<ApiParam name="libraryId" type="string" required>
  The library ID obtained from `resolve-library` (e.g., `/vercel/next.js`, `react`, `hono`)
</ApiParam>

<ApiParam name="query" type="string" required>
  The question or task you need help with. Be specific for better results.
</ApiParam>

<ApiParam name="limit" type="number">
  Maximum results to return (1-10, default 5)
</ApiParam>

<ApiParam name="tokens" type="string">
  Response format: `full`, `compact`, `code-only`, or `summary`
</ApiParam>

---

## Query Tips

### Good Queries

```
✓ "How to set up authentication with JWT"
✓ "Server component data fetching patterns"
✓ "Form validation with error messages"
✓ "useEffect cleanup function best practices"
```

### Poor Queries

```
✗ "auth" (too vague)
✗ "help" (not specific)
✗ "how do I do the thing" (unclear)
✗ "react" (library name, not a question)
```

## Response Formats

| Format | Tokens | Best For |
|--------|--------|----------|
| `full` | ~5,000 | Debugging, exploration |
| `compact` | ~2,000 | Normal usage (recommended) |
| `code-only` | ~1,000 | Quick code examples |
| `summary` | ~500 | Check if results exist |

### Code-Only Response

```json
{
  "name": "query-docs",
  "arguments": {
    "libraryId": "react",
    "query": "useEffect cleanup function",
    "tokens": "code-only"
  }
}
```

Returns only the code blocks, minimal prose:

```typescript
useEffect(() => {
  const subscription = dataSource.subscribe();
  return () => {
    subscription.unsubscribe();
  };
}, [dataSource]);
```

## Response Schema

```typescript
interface QueryDocsResponse {
  success: boolean;
  libraryId: string;
  libraryName: string;
  version: string;
  query: string;
  resultCount: number;
  results: Array<{
    title: string;
    content: string;
    contentType: 'prose' | 'code' | 'mixed';
    sourceFile: string;
    relevanceScore: number; // 0-1
  }>;
}
```

## Error Handling

| Error | Cause | Solution |
|-------|-------|----------|
| `libraryId is required` | Missing library ID | Call `resolve-library` first |
| `Library not found` | Invalid library ID | Use `resolve-library` to find valid ID |
| `Library not yet indexed` | Library still processing | Wait and retry later |
| No results | Query doesn't match | Try different search terms |

---

## Notes

- Results are ranked by **semantic similarity**, not keyword matching
- Each result includes the **source file** for reference
- Large documentation libraries may have more relevant results
- The `tokens` parameter helps manage response size for token efficiency
- Queries are processed using vector embeddings for conceptual matching
