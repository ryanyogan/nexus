# Save Project Context

Store project information so your AI remembers it across sessions.

## Why Save Context?

Without memory, you re-explain your project every session:

> "This is a monorepo using Turborepo. We use TypeScript, Hono for the API, React for frontend. We deploy to Cloudflare. Our auth uses JWT..."

With Nexus memory, you say this **once** and recall it forever.

---

## Quick Start

## Memory Types

| Type | Use For | Example |
|------|---------|---------|
| `project_context` | Tech stack, architecture, conventions | "Monorepo with Turborepo" |
| `decision` | Architectural decisions with rationale | "Using JWT because..." |
| `session_summary` | What was accomplished | "Implemented user auth" |
| `correction` | Lessons learned, things to avoid | "Don't use library X because..." |

### Project Context

> "Remember our project architecture: Monorepo with apps/web (Next.js), apps/api (Hono), and packages/shared"

### Decisions

> "Remember that we decided to use Drizzle instead of Prisma because of edge runtime support"

### Corrections

> "Remember: don't suggest using moment.js - we use date-fns instead"

## Best Practices

### Name Your Project

Always specify a project name for organization:

> "Save this to project 'my-app': We use Tailwind CSS with the default config"

### Use Tags

Tags help with semantic search:

> "Remember (tags: auth, security): We use httpOnly cookies for JWT storage"

### Be Specific

```
❌ "We use React"
   → Too vague

✓ "We use React 18 with Server Components in Next.js App Router"
   → Specific and searchable
```

### Include Rationale

For decisions, include the *why*:

```
❌ "We use Drizzle"

✓ "We use Drizzle instead of Prisma because:
   1. Edge runtime support
   2. SQL-like syntax we prefer
   3. Smaller bundle size"
```
