# Memory Best Practices

Learn how to effectively use Nexus memory for persistent project context.

## Why Memory Matters

Every AI session starts fresh. Without memory, you waste tokens re-explaining:

- Project architecture
- Tech stack and conventions
- Past decisions and rationale
- Lessons learned

Nexus memory solves this by storing context that persists across sessions.

---

## Memory Types

Use the right type for each piece of information:

### Decisions

**Use for**: Architectural choices with rationale

<Terminal title="Save a decision">

## Organization Strategies

### Name Projects Consistently

Always use consistent project names:

```
✓ "my-app"
✓ "my-app"
✓ "my-app"

✗ "my-app"
✗ "myApp"
✗ "My App"
```

### Use Tags

Tags enable powerful filtering:

> "Remember (tags: auth, security): We use httpOnly cookies for JWT storage to prevent XSS attacks"

Common tag categories:
- **Feature**: `auth`, `payments`, `notifications`
- **Layer**: `api`, `frontend`, `database`
- **Priority**: `important`, `deprecated`

### Set Importance

High importance memories surface first:

> "Remember this is important (importance: 9): Never commit .env files"

Scale: 1 (low) to 10 (high)

## Memory Lifecycle

### Creating Memories

Be specific and include context:

```
❌ "Remember we use React"
   Too vague

✓ "Remember: We use React 18 with Server Components.
   The app router is in apps/web.
   We follow the container/presentational pattern."
   Specific and actionable
```

### Updating Memories

When things change:

> "Update the database decision: We migrated from Prisma to Drizzle last month"

### Archiving Outdated Memories

Mark deprecated information:

> "Mark the 'old API structure' memory as deprecated - we refactored this"

## Example: New Project Setup

When starting a new project, establish context:

<StepList>
  <Step title="Project Architecture">
    "Remember: This is a monorepo with Turborepo. apps/web is Next.js, apps/api is Hono on Workers, packages/db has Drizzle schema."
  </Step>
  <Step title="Tech Stack">
    "Remember our stack: TypeScript, pnpm, Tailwind CSS, shadcn/ui components, Cloudflare for deployment."
  </Step>
  <Step title="Conventions">
    "Remember our conventions: Use barrel exports, prefer named exports, put types in separate .types.ts files."
  </Step>
  <Step title="Initial Decisions">
    "Remember decision: Using Hono instead of Express because it runs on edge and has better TypeScript support."
  </Step>
</StepList>

## Team Usage

### Shared Project Context

Multiple team members can contribute to the same project's memory:

```
Team Member A: "Remember the API uses v2 endpoints"
Team Member B: "Remember we standardized on ISO 8601 dates"
```

Both contributions are available to the whole team.

### Individual vs Team Memory

- **Project context**: Shared across team
- **Personal preferences**: Keep in personal project

### Conflict Resolution

If memories conflict, the most recent wins. Update old memories:

> "Update the 'API structure' memory to reflect we moved to v2"

## Troubleshooting

### Memory Not Found

Check project name spelling:

```bash
nexus memory list --project my-app
```

### Too Many Results

Filter by type or tags:

> "Search memories about auth, only decisions"

### Authentication Required

Memory writes require login:

```bash
npx @nexus/cli auth login
```
